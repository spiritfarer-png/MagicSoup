# 遗物系统

## 目标与范围

遗物是一种特殊素材。它既能作为独立遗物留在素材背包中，在每回合开始时产生效果；也能像普通素材一样进入合成栏并被合成为卡牌的一部分。两种身份由素材当前所在位置决定，不额外保存“启用遗物效果”状态。

本轮实现遗物数据、战斗快照、回合开始结算、战斗 HUD 展示、测试资源，以及与遗物结算相关的护甲清空流程调整。暂不实现 Tooltip、DOTween 动效、`CardEntity` World UI 改造、卡牌升级入口和战斗结算界面。

## 数据结构

- 使用 `RelicMaterialData : CardMaterialData` 表示遗物素材，不采用接口或独立背包数据类型。
- `RelicMaterialData` 提供独立的 `CreateAssetMenu` 创建入口。
- 子类新增不可升级的 `relicIntents` 数组；允许数组为空。
- 继承的 `normalIntents / ascendedIntents` 是遗物被合成进卡牌后使用的卡牌意图。
- `relicIntents` 只在遗物作为独立背包遗物参与战斗时使用，永远不会因为卡牌升级而改变。
- 遗物数组直接保存 `RelicMaterialData` 资产引用，不建立 `RelicMaterialInfo` 运行时实例。数组中重复出现同一资产引用，表示多份独立遗物。
- 不为遗物生成实例 ID，不对相同资产去重。
- 意图继续统一使用现有 `Intent`。未来通过扩展 `ActionType` 表达更多遗物效果，不增加目标枚举。
- 本轮遗物意图只实现 `Attack`。开发者负责保证不为背包遗物配置 `Defend / Heal` 等当前没有遗物语义的类型，运行时不增加合法性检查。

## 背包、合成与升级

- 遗物继续使用现有素材背包、素材槽位、合成栏与拖拽换位逻辑，不建立独立遗物背包。
- 遗物素材不堆叠；同一种遗物可以存在多份，每份分别占用一个素材槽位。
- 只有位于 `InventoryManager.materialSlots` 中的遗物会进入下一场战斗的玩家遗物快照。
- 位于 `craftingSlots` 中但尚未合成的遗物不触发背包遗物意图；拖回素材背包后恢复遗物身份。
- 遗物可以单独合成一张卡，也可以和普通素材或其他遗物混合合成。
- 合成后遗物占卡牌最多三个素材位置中的一个，参与素材顺序、图标叠放、汤色混合、名称拼接和初始生命计算。
- 遗物合成进卡牌后，只使用继承的 `normalIntents / ascendedIntents`，绝不触发 `relicIntents`。
- 遗物素材所在卡牌升级时，和其他素材一起使用 `ascendedIniHealth / ascendedIntents`；`relicIntents` 不升级。
- 当前不实现拆解。未来若拆解出遗物，它恢复为普通、未升级的背包遗物。

## 战斗快照

- `BattleManager` 内部保存玩家与敌方两组遗物数组，并向 HUD 提供只读访问。
- 玩家遗物快照在 `BattleManager.InitializeBattle()` 最开始建立：按素材背包槽位顺序扫描，只提取 `RelicMaterialData`，忽略普通素材和空槽。
- 玩家快照是紧凑数组，只保留遗物之间的相对顺序，不保留原背包空槽位置。
- 玩家遗物列表在开战时锁定。本场战斗中即使以后允许修改背包，也不改变当前快照；变化从下一场战斗生效。
- 快照只锁定遗物资产引用和顺序，不深拷贝 ScriptableObject 中的静态意图配置。
- 敌方遗物由 `BattleManager` Inspector 数组配置，并按数组顺序触发；允许空引用，运行时统一忽略。
- 玩家遗物数组也保留 Inspector 配置以便直接运行测试场景。只有场景中不存在 `InventoryManager` 时才使用该测试配置；存在背包但没有遗物时，玩家快照必须为空。
- 不在战斗代码中限制遗物数量。HUD 排列由 Layout Group 配置。
- 双方至少有一张参战卡由开发者保证，不增加零卡牌初始化检查。

## 回合阶段与结算顺序

- 新增统一的 `RelicResolving` 战斗阶段，不为玩家和敌方分别增加枚举；该阶段会在双方各自的遗物结算窗口进入一次。
- `RelicResolving` 期间所有按钮禁用，卡牌点击无效。
- 初始化只建立遗物快照，不额外触发遗物。第一回合仍通过第一次 `StartRound()` 触发一次。
- 每回合每份遗物只完整行动一次；玩家额外行动不会再次触发遗物。
- 每份遗物按自身 `relicIntents` 数组顺序逐条判断并执行；条件不满足的意图直接跳过。
- 每条意图判断时实时读取 `BattleClock.currentTime`，不缓存整轮或整次遗物行动的时钟值。未来意图若修改时钟，后续遗物和卡牌按新时钟继续判断。

每回合顺序为：

1. 新回合开始，推进全局时钟。
2. 清空玩家所有存活卡牌的护甲。
3. 进入 `RelicResolving`，玩家遗物按玩家快照数组顺序触发。
4. 战斗未结束时进入玩家决策阶段；玩家可使用一次额外行动，然后点击结束回合。
5. 玩家卡牌按既定顺序完成正常行动。
6. 战斗未结束时，清空敌方所有存活卡牌的护甲。
7. 再次进入 `RelicResolving`，敌方遗物按 Inspector 快照数组顺序触发。
8. 战斗未结束时，敌方卡牌按既定顺序完成正常行动。
9. 战斗未结束时进入下一回合。

新的护甲周期含义：

- 玩家护甲在下个回合开始时清空，因此能抵挡本回合敌方攻击。
- 敌方护甲在其下一次正常行动开始前清空，因此能抵挡下一回合的玩家遗物、额外行动和玩家正常行动。
- 敌方上一轮留下的护甲覆盖完整玩家攻击窗口：玩家遗物 → 额外行动 → 玩家正常行动。

## 遗物意图与胜负

- 玩家遗物的 `Attack` 固定攻击敌方最左侧存活卡牌。
- 敌方遗物的 `Attack` 固定攻击玩家最右侧存活卡牌。
- 每条 `Attack` 执行时重新寻找当前前排。同一遗物连续攻击击杀目标后，下一条攻击可以转向新的前排。
- 遗物不是场上单位，不参与双方存活数量计算，也不能阻止战斗结束。
- 每条实际执行的遗物意图结束后立即检查胜负。
- 玩家遗物结束战斗时，停止剩余玩家遗物、玩家决策与行动、全部敌方遗物以及本回合后续流程。
- 敌方遗物结束战斗时，停止剩余敌方遗物以及本回合后续流程。
- 玩家遗物与玩家卡牌行动都先于敌方遗物结算；玩家侧流程先杀光敌方时，敌方遗物不会获得反向结算机会。
- 卡牌意图与遗物意图使用不同的上层执行入口，避免让遗物伪装成 `CardEntity`；二者共用底层前排查找和胜负检查能力。
- Console 遗物日志包含阵营与遗物素材名，例如 `[玩家遗物] 铜铃`、`[敌方遗物] 毒瓶`。目标卡牌继续输出受伤与死亡日志；条件不满足的意图不打印。

## 战斗 HUD

- 遗物由 `BattleHUDView` 管理，不作为 World UI，也不参与卡牌世界交互。
- HUD 分别提供玩家遗物容器和敌方遗物容器。
- 双方图标均按对应快照数组顺序从左到右生成；空引用不生成图标，不保留空位；重复遗物生成多个相同图标。
- 布局尺寸、间距、换行和方向交由 Unity Inspector 中的 Layout Group 配置，代码不写死上限或布局参数。
- 使用独立的简单遗物图标 Prefab，不复用带拖拽行为的 `MaterialSlotUI`。
- 新增 `RelicIconUI`，只负责保存绑定后的只读 `RelicMaterialData` 引用并设置 `Image.sprite`，不负责触发、排序、点击或 Tooltip。
- HUD 在 `OnOpen()` 时根据已建立的快照生成一次图标；当前战斗中不监听动态变化，关闭时清理生成对象。
- 当前遗物图标不可点击、不可拖拽、没有悬停反馈，也不参与额外行动选牌。未来由统一 Tooltip 系统覆盖素材、卡牌和遗物。
- 战斗结束进入 `BattleOver` 后遗物图标继续显示，直到 HUD 关闭或场景销毁。

## 测试配置

- 创建至少一个 `RelicMaterialData` 测试资源。
- 测试遗物的 `relicIntents` 配置为无条件攻击 1 点。
- 同一资源继承的卡牌 `normalIntents` 配置为不同数值，例如无条件攻击 3 点，以便确认两套意图不会混用。
- 在玩家初始素材背包中放入一份测试遗物，验证玩家快照、顺序与合成身份切换。
- 在 `BattleManager.enemyRelics` 中配置一份测试遗物，验证敌方触发与自动目标。
- HUD 同时显示双方遗物图标。

## 本轮不实现

- 遗物或素材 Tooltip。
- 遗物点击、拖拽和触发动效。
- DOTween 卡牌表现与 `CardEntity` World UI 改造。
- 卡牌升级事件及已升级卡重新初始化的修正。
- 战斗结算界面与返回按钮。
- `Attack` 以外的新遗物 `ActionType`。
