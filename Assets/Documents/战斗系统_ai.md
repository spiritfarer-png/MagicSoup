# 战斗系统（测试阶段）

## 目标与范围

本阶段用于验证“部署卡牌 → 测试战斗”的战斗链路。正式版本不会切换场景；当前测试阶段从 `SelectScene` 直接加载 `TestBattleScene`。本阶段不实现战斗结算界面和返回主场景交互。

本阶段不做奖励、掉落、药品效果、敌人专用数据资产、场内行动日志、复杂动画、拖拽、目标选择或中途退出。遗物规则与实现范围详见 `遗物_ai.md`；药品只保留禁用按钮占位。

## 卡牌与战斗状态

- 玩家和敌人使用完全相同的瓦罐汤卡牌结构：一张卡由最多三份按顺序保存的素材组成，名称、初始生命、汤色、图层和意图都由素材生成。
- 敌方测试卡直接嵌入 `TestBattleScene` 的战斗管理器中，以完整 `CardInfo` 配置四个槽位；不创建敌人专用 ScriptableObject。空槽允许存在并被忽略。
- 进入战斗后，每张参战卡都会创建独立 `BattleCardState`，其中保存当前生命、护甲和死亡状态。
- `CardInfo` 只保存组合数据、初始生命与升华状态；不保存当前生命，也不存在攻击力字段。
- 初始生命不是生命上限。`Heal` 可以使当前生命超过初始生命。
- 每场战斗开始时，所有参战卡的当前生命重置为初始生命、护甲为 0；战斗结束后丢弃所有战斗状态。返回主场景时，部署中的原卡仍在原槽位，视为恢复初始生命。
- 升华卡依据 `CardInfo.isAscended` 使用素材的升华生命与升华意图，敌我规则一致。

## 场地、槽位与卡面

- 战场左侧为玩家、右侧为敌人；双方都固定横向显示四个从左到右的槽位。
- 槽位不会因空位或死亡收缩、补位或重排。死亡卡牌立即隐藏，原位保持空白。
- 玩家第 4 槽（最右）是敌方优先攻击的前排；敌方第 1 槽（最左）是玩家优先攻击的前排。
- 战斗场卡面复用完整 `CardViewUI`：显示素材组合、名称、当前生命与护甲。第二数值用于护甲，护甲为 0 时隐藏；战斗外的背包和部署卡面只显示初始生命并始终隐藏护甲。
- 战场不显示槽位编号、阵营标题、回合数或场内日志；显示简单的当前全局时钟数字，后续替换为正式时钟 UI。

## 全局时钟

- 时钟范围为 0～11，初始运行值为 0。显示的时候会+1，也就是1~12
- 时钟跨战斗继承，不会因进入、结束或返回战斗而重置。
- 每个回合开始时推进一次：`(当前值 + 1) mod 12`。因此第一场战斗的首回合使用时钟 1；若上一场结束为 5，下一场首回合使用 6。
- 同一回合内时钟固定。额外行动、玩家正常行动和敌方正常行动全部读取这一回合的同一个值。

## 回合流程

战斗固定由玩家先手。进入测试场景后先生成双方卡牌、显示时钟，并禁用所有操作；初始化完成后自动开始第一个回合。

每回合流程如下：

1. 新回合开始，时钟推进一次并刷新显示。
2. 只清空玩家所有存活卡牌的护甲。数值立即刷新，护甲文字按需隐藏；不播放动画、不打印日志。
3. 触发玩家背包遗物。
4. 进入玩家决策阶段。
5. 玩家点击“结束回合”后，自动结算玩家正常行动：槽位 4 → 1（右→左）。
6. 玩家正常行动结束且战斗未结束时，清空敌方所有存活卡牌的护甲。
7. 触发敌方遗物。
8. 战斗未结束时，自动结算敌方正常行动：槽位 1 → 4（左→右）。
9. 敌方正常行动结束且战斗未结束时，立即进入下一个回合。

自动结算中，两张卡牌行动的起点间隔为 0.5 秒，可在 Inspector 调整；每张卡先高亮 0.25 秒，随后连续执行完整行动。单张卡内部的多个意图不额外等待。

## 行动与意图

- 卡牌轮到行动前已死亡，直接跳过，不触发任何意图。
- 即使当前时钟下没有满足条件的意图，存活卡仍会进行 0.25 秒行动高亮并视为完成一次行动。
- 一次完整行动按素材放入顺序结算：第 1 份素材的全部意图 → 第 2 份 → 第 3 份；每份素材内部按意图数组顺序结算。
- 每条意图只依据当前全局时钟判断：`None` 永远满足；`Equal` 相等；`NotEqual` 不相等；`Less` 严格小于；`Greater` 严格大于。不引入生命、护甲、位置等其他条件。
- 每条具体意图效果执行后立即检查胜负。任意一方全灭立即结束，取消未执行的意图和后续行动。
- 若行动者在自己的意图中死亡，立即隐藏卡面并停止该卡剩余意图。

当前意图效果：

- `Attack.value`：对目标造成固定伤害。攻击力不是卡牌或素材的数值；伤害只来自该意图的 `value`。每一条 Attack 执行时重新寻找目标，因此连续攻击可在击杀后立即转向下一张存活前排卡。目标不存在时该攻击无效，仍检查胜负。
- `Heal.value`：行动者自身恢复固定生命，无上限。
- `Defend.value`：行动者自身获得固定护甲，可叠加、无上限；受到伤害时先扣护甲，剩余伤害再扣生命。玩家护甲在下个回合开始时清空；敌方护甲在其下一次正常行动开始前清空，因此双方护甲都能覆盖对方下一段攻击窗口。
- 攻击不会触发自动反击；未来只有明确意图才能造成反击或其他额外效果。

## 目标与胜负

- 玩家卡牌的 Attack 自动攻击敌方最左边仍存活的卡牌。
- 敌方卡牌的 Attack 自动攻击玩家最右边仍存活的卡牌。
- 玩家不可手动选择攻击目标。Heal、Defend 默认作用自身。
- 当前生命小于或等于 0 时立即死亡。
- 敌方全灭且玩家仍有存活卡牌时为胜利；玩家全灭时为失败；同一次效果导致双方全灭时为失败。
- 战斗结束后进入 `BattleOver`，禁用战斗 HUD 与场上卡牌交互。胜负文字、结算界面和返回按钮本阶段不实现；时钟值仍不重置。

## 玩家输入与反馈

| 所在状态 | 用户输入 | 游戏反馈 |
| --- | --- | --- |
| 主场景部署区为空 | 点击“进入战斗” | 按钮置灰且不可点击；不显示额外提示。 |
| 主场景部署区有至少一张卡 | 点击“进入战斗” | 直接加载 `TestBattleScene`，无加载动画或过渡。 |
| 战斗初始化中 | 点击任意战斗按钮或卡牌 | 所有操作均禁用，无效果。 |
| 玩家决策阶段 | 点击“额外行动” | 进入选牌模式；该按钮立刻禁用，未使用的额外行动机会保留。 |
| 额外行动选牌模式 | 鼠标悬停己方存活卡 | 卡面使用统一高亮效果；移出即取消高亮。 |
| 额外行动选牌模式 | 点击己方存活卡 | 该卡立刻完整行动一次；高亮持续整个行动。无论是否触发意图，都消耗本回合机会。结束后立刻回到决策阶段，“结束回合”可用，“额外行动”保持禁用。 |
| 额外行动选牌模式 | 点击“取消选择” | 取消选牌模式，不消耗机会；重新启用“额外行动”按钮。 |
| 额外行动选牌模式 | 点击敌方卡、空槽、空白处、药品按钮或其他非卡牌 UI | 无效果，保持选牌模式。 |
| 非选牌模式 | 点击任意战斗卡牌 | 无效果。 |
| 玩家决策阶段或选牌模式 | 点击“结束回合” | 取消选牌模式（如有），立即禁用全部操作并开始不可撤回的自动结算。 |
| 自动结算期间 | 点击按钮、卡牌或尝试拖拽 | 全部禁用，无效果；战斗卡牌不允许拖拽。 |
| 任意阶段 | 点击药品按钮 | 按钮始终禁用，无效果，不占用额外行动。 |
| 战斗结束 | 点击场上卡牌、按钮或尝试拖拽 | 场上交互全部关闭，无效果；本阶段不提供结算或返回按钮。 |

## 视觉与调试反馈

- 悬停选牌与卡牌行动共用同一种高亮效果。悬停高亮随鼠标移开消失；行动高亮持续 0.25 秒，且只高亮行动者，不高亮目标。
- 受伤、治疗、获得护甲、护甲清空和死亡都会立刻刷新卡面；死亡立即隐藏。
- 不做移动、飞行物、受击特效、尸体、死亡特效或场内行动日志。
- Unity Console 只打印实际执行的意图、伤害/治疗/护甲结果、死亡与胜负；条件不满足的意图不打印。日志包含行动者名称与阵营、目标及实际数值。攻击日志应同时体现护甲吸收量与实际生命伤害；护甲完全吸收时也记录生命伤害为 0。

## 后续扩展边界

- 未来新增意图时，可为其定义独立目标策略和效果，不改变当前“素材顺序 → 意图数组顺序”的结算骨架。
- 正式战斗将改为当前场景内切换 UI，而非场景加载；测试战斗的战斗管理器、运行时槽位生成和 `BattleCardState` 应尽量可复用。
- 药品、正式时钟 UI、奖励、关卡敌人生成、动画与战斗内日志均留待后续阶段实现；遗物按 `遗物_ai.md` 实现。
